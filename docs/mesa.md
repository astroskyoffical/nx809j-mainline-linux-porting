# Mesa A840 userspace variant

The original Debian 13 rootfs uses Mesa `25.0.7-2+deb13u1`. That version predates Mesa 26's Freedreno Gen8 and A840 device support, so the original rootfs is not the right userspace baseline for the A840. Mesa 26.0.0's release notes list the Gen8 Freedreno work, the A8xx device, and A840/X2-85 device information. The upstream [A840 device-info commit](https://gitlab.freedesktop.org/mesa/mesa/-/commit/6e3598177b8ed02f06ebbeeaca865b7cfcbbe87b) is a feature commit within Mesa, not the complete source revision used to build the Debian binaries. It adds the Mesa device-info ID `0xffff44050A31` and A8xx generation properties. Its commit message notes that memory-bus and clock differences remain, while the UMD programming model is architecturally similar. [Mesa 26.0.0 release notes](https://docs.mesa3d.org/relnotes/26.0.0.html)

The binary runtime provenance is Debian source package `mesa 26.1.6-1~bpo13+1` from frozen snapshot `20261019T000000Z`. Its source index (`Sources.xz`) SHA-256 is `5a63801795c00dcda6508df8f778fdc2fc24a4a6a82edc9beb9ba11c66e9fa1b`; the `.dsc` SHA-256 is `e5441f12555341fa6060d99a0d111b96a4850dd13ab2847afca26a1a33cbffb2`, and the upstream source tar SHA-256 is `5296b88a0f1e012e2cb9ada150a2bbadf728ca81e5a4fb2ab43c83a4d2158606`. The ARM64 binary package versions and hashes are listed in each variant's `mesa-dependencies.txt`, with the backports Release and `Packages.xz` hashes in its manifest.

The phone FDT GPU base ID is recorded as `0x44050a01`; it does not directly match Mesa's `0xffff44050A31` device-info entry. The pinned kernel code adds the active A8xx slice count into bits 7:4, so three slices would produce `0x44050a31` and match the entry. The phone's active slice count and runtime GPU match have not been verified. Older artifacts retain the legacy field names `mesa_source_commit` and `a840_chip_id`; in those files they refer to the feature commit and Mesa's device-info entry, not a phone-confirmed chip ID or full Mesa source pin. New build metadata uses separate, explicit fields.

Debian Trixie backports publishes ARM64 Mesa `26.1.6-1~bpo13+1` from the frozen 2026-10-19 snapshot. Its `mesa-vulkan-drivers` dependency requires glibc `>= 2.39`; the base rootfs has `libc6 2.41-12+deb13u4`. The snapshot's arm64 package index contains the matching runtime set. APT selected six Mesa package upgrades and one new stable dependency, `libdisplay-info2`; the complete installed-package delta is in the artifact folder.

The preserved Mesa-only variant was built from the original generic rootfs archive without changing it. It retains Debian 13, records the exact backports source and snapshot metadata, and adds the Freedreno GL DRI driver, Vulkan driver, and ICD manifest. The output manifest now records Debian source package `mesa 26.1.6-1~bpo13+1`, the frozen snapshot, source index/`.dsc`/upstream tar hashes, and the separate A840 device-info commit. It also keeps the FDT GPU base ID `0x44050a01` separate from the Mesa device-info ID `0xffff44050A31`; the conditional three-slice mapping and active phone slice count remain unverified. Set `MESA_BASE_ID` only when intentionally selecting a specific archived rootfs; selecting the preserved generic base produces a Mesa-only comparison variant under `artifacts/mesa/`.

This establishes that the selected Debian ARM64 Mesa build contains the upstream A840 device information and Gen8 userspace code. It does not prove the NX809J mainline kernel exposes all required MSM DRM interfaces, that firmware and device-tree setup are complete, or that the phone renders through either driver. Denial package installation and systemd unit checks are static only; the integrated filesystem remains unqualified on phone hardware.
