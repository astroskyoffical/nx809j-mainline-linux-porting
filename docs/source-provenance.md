## Mainline and OnePlus 15 port comparison

The upstream Linux 7.3 tree has the Kaanapali SoC description and MTP/QRD board files, but no NX809J/RedMagic board file. The XEC fork supplies a concrete OnePlus 15 `infiniti` board port for the same SoC. This is a serious starting reference; it means absence of an NX809J DTS in the upstream package does not imply the platform lacks working mainline-based support.

Compared with Linux 7.3, the XEC 7.3-rc4 tree adds three OnePlus `infiniti` DT/overlay files, two OnePlus panel drivers, and five Synaptics TCM core/SPI files. It shares 34 Kaanapali-named paths with upstream; five shared blobs differ. XEC master 7.3-rc6 has the same OnePlus board, panel, and touch blobs as the 7.3-rc4 pin. The older Codelinaro 6.17-rc6 branch has 29 Kaanapali-named paths versus 34 in Linux 7.3; 18 of its 26 shared Kaanapali-named blobs differ. It carries Kaanapali CAMSS and Iris platform references that are absent from upstream 7.3, but those files alone do not establish a working camera path.

The 2026-10-19 read-only device capture recorded NX809J compatibles `qcom,canoe-mtp` / `qcom,canoe`, panel `qcom,mdss_dsi_bf375_rm692h5_6p8_magic_dsc_cmd`, and a `synaptics,tcm-spi` touchscreen on GENI SPI19. The XEC OnePlus tree instead uses `oneplus,infiniti` and its global/China panel compatibles. Its TCM SPI driver does match `synaptics,tcm-spi` as well as `synaptics-s3910`, making it a relevant source candidate for the NX touch controller. The NX touch IC identity, rail timing, GPIOs, and panel electrical sequence still require validation against this phone. The XEC 7.3-rc4 commit also adds a Samsung S5KJN5 sensor driver; that does not prove that every NX camera works.

The [Nura OnePlus 15 page](https://wiki.nura.eco/wiki/OnePlus_15_%28oneplus-infiniti%29) reports storage, battery, screen, touch, 3D, Wi-Fi, Bluetooth, and NFC working; audio, camera, cellular calls/SMS/data, GPS, DisplayPort, fingerprint, and sensors broken; and USB requiring PD. A separate [SM8850 component summary](https://wiki.nura.eco/wiki/Qualcomm_Snapdragon_8_Elite_Gen_5_%28SM8850-AC%29) describes broader display/GPU/camera/suspend support. Keep that difference visible: the device-specific page reports camera failure despite the broader SoC summary. These are OnePlus/Nura test reports, not NX809J results.

The NX809J driver reconstruction repository remains separate from both kernels. Its manifest marks candidates incomplete and hardware validation deferred. Android vendor modules cannot be assumed to load in upstream Linux; driver source, firmware availability, board wiring, and real device tests each need independent evidence. The XEC firmware collection and OnePlus vendor sources are model-specific references; do not substitute their firmware or boot policy on the NX809J.

## Limits and handling

- The project snapshots pin one commit per repository and omit older Git history. Large kernel and firmware repositories use `blob:none` project clones; full build worktrees are kept on WSL ext4.
- The NX809J vendor tree contains prebuilt Android/kernel artifacts and repository-authored EDL instructions. Do not run bundled binaries or follow flashing instructions as part of source acquisition.
- The vendor tree’s GPL notice and missing-source report are claims made by that repository. The source set was not legally audited, and root-level kernel licensing does not establish rights to redistribute vendor modules, firmware, or recovery/boot artifacts.
- Acquiring sources and comparing DTS strings does not build a kernel, validate Denial packaging, test a driver, prove bootloader acceptance, or verify recovery on the phone. No phone operation was performed by this source task.
